# SSH Config Support

SSH_Lib.Config implements a narrow OpenSSH-style config subset for Git-over-SSH transport use.

Supported directives:

- `Host`
- `HostName`
- `User`
- `Port`
- `IdentityFile`
- `IdentitiesOnly`

Config resolution preserves secure session defaults unless a supported directive explicitly overrides the relevant field. `ProxyJump` is resolved as data in `Session_Options.Proxy_Jump`; `Sessions.Open` implements it as SSH-over-SSH `direct-tcpip` forwarding. `ProxyCommand` is resolved as data in `Session_Options.Proxy_Command`; `Sessions.Open` executes it only as an explicit subprocess-backed transport after applying OpenSSH-style `%h`, `%p`, `%r`, and `%%` token expansion. `ConnectionAttempts` is resolved into `Session_Options.Connection_Attempts` and bounds retry attempts for retryable live connection setup failures across direct, ProxyCommand, ProxyJump, and existing ControlMaster connection paths. After authentication, live transcripts honor `ServerAliveInterval` and `ServerAliveCountMax` by sending bounded `keepalive@openssh.com` global requests on internally-driven idle read timeouts and failing after the configured missed-reply count; explicit caller read timeouts still surface as timeouts. `RekeyLimit` maps OpenSSH-style byte suffixes and optional duration values such as `1G 1h` onto the automatic rekey byte and elapsed-time thresholds. Direct live connections honor `AddressFamily inet`, `inet6`, or `any` when selecting resolved socket addresses, bind `BindAddress` to the matching local address family before connecting, apply `BindInterface` with the Linux `SO_BINDTODEVICE` socket option when configured, apply `TCPKeepAlive`, and map the first `IPQoS` token to the TCP socket traffic-class/TOS option where the platform supports it. Host-key verification honors `NoHostAuthenticationForLocalhost` for `localhost`, `localhost.localdomain`, `127.*`, and loopback IPv6 targets when no `HostKeyAlias` is configured; TOFU writes via `Append_Trusted_Host`/`Sessions.Open` honor `HashKnownHosts` with OpenSSH-style hashed selectors. `PasswordAuthentication no`, `PubkeyAuthentication no`, and `KbdInteractiveAuthentication no` remove those methods from session-open authentication preflight and live userauth attempts. `NumberOfPasswordPrompts` limits password-style authentication; `0` disables password and keyboard-interactive prompting. `CheckHostIP yes`, `UpdateHostKeys ask`, `UpdateHostKeys yes`, `VerifyHostKeyDNS yes`, and `VerifyHostKeyDNS ask` fail closed with `Unsupported_Feature` until those host-key backends are implemented; their `no` forms remain accepted no-ops. `HostbasedAuthentication`, `EnableSSHKeysign`, `GSSAPIAuthentication`, `GSSAPIDelegateCredentials`, `ForkAfterAuthentication`, `ProxyUseFdpass`, and non-`no` `AddKeysToAgent` values also fail closed at session-open preflight until those backends exist. `FingerprintHash sha256` or `md5` selects the OpenSSH fingerprint image used by `KnownHostsCommand` `%f` expansion. Configured exec, shell, and subsystem helpers honor `StdinNull` by sending channel EOF immediately after successful channel setup. `ControlMaster`, `ControlPath`, `ControlPersist`, `BatchMode`, `ForwardAgent`, `ForwardX11`, `RequestTTY`, `RemoteCommand`, `LogLevel`, `VisualHostKey`, `StrictHostKeyChecking`, `CanonicalDomains`, `CanonicalizeMaxDots`, `CanonicalizeFallbackLocal`, `CanonicalizePermittedCNAMEs`, `EscapeChar`, `SessionType`, `LogVerbose`, `CASignatureAlgorithms`, `KnownHostsCommand`, `PermitLocalCommand`, `LocalCommand`, `ClearAllForwardings`, and `ExitOnForwardFailure` are resolved as session data. `LocalForward`, `RemoteForward`, and `DynamicForward` are resolved as line-separated session data in `Session_Options.Local_Forwards`, `Remote_Forwards`, and `Dynamic_Forwards`; `SSH_Lib.Config_Apply` can start local, dynamic, and remote managed services from those resolved values, can apply combined `ExitOnForwardFailure` policy with `Start_Configured_Forwards`, and can also request remote forwards without starting a managed worker. When `ClearAllForwardings` resolves to true, those apply helpers return success with zero started services or requested remote forwards while leaving the resolved forward data inspectable. `SendEnv` and `SetEnv` are resolved as line-separated data in `Session_Options.Send_Env` and `Set_Env`; `SSH_Lib.Config_Apply.Apply_Configured_Environment` sends the resulting RFC 4254 `env` requests on a caller-supplied channel, `Open_Configured_Exec` automatically applies them before the exec request while honoring `RemoteCommand`, `SessionType none`, and `RequestTTY yes/force` PTY setup, `Open_Configured_Subsystem` applies them before the subsystem request while using `RemoteCommand` as the subsystem name when present, and `Open_Configured_Shell` applies them before shell or PTY-shell setup selected from `RequestTTY`. `SendEnv` wildcard patterns match the bounded environment list exposed by `SSH_Lib.Platform.Environment`; exact names still use `Getenv`. `ProxyCommand none` is normalized to an empty proxy command and uses the normal direct transport path. General config resolution does not shell out. ProxyCommand expansion supports the OpenSSH ProxyCommand token set `%h`, `%n`, `%p`, `%r`, and `%%`; unknown percent pairs are preserved literally. `Config_Apply.Expand_Known_Hosts_Command` provides caller-owned `KnownHostsCommand` expansion for `%f`, `%h`, `%H`, `%I`, `%K`, `%l`, `%L`, `%n`, `%p`, `%r`, `%t`, and `%%` without executing the command.

`ControlMaster` values are classified as disabled, no, yes, ask, auto, autoask, or invalid by `SSH_Lib.Config_Apply.Control_Master_Mode_Of`. `RequestTTY` is classified as auto, no, yes, force, or invalid, and `SessionType` is classified as default, none, subsystem, or invalid. `ControlPath` expansion is deterministic and data-only: `Expand_Control_Path` supports leading `~`, `%%`, `%h`, `%n`, `%p`, `%r`, `%l`, `%L`, and `%C`, and rejects unknown tokens or control characters. `Control_Persist_Seconds` parses `ControlPersist` values such as `10m`, `1h30m`, `2d`, `yes`, and `no` into bounded seconds. `Plan_Control_Master` expands the path and chooses reuse/start/ask actions; an existing path is considered reusable only when mux version-4 hello negotiation and an alive-check succeed over the Unix-domain control socket. `Start_Planned_Control_Master` starts planned caller-owned control masters, records the expanded path and persist seconds, and gates ask/autoask starts through `Control_Master_Approval_Callback`, returning `Cancelled` if approval is missing or denied. `Sessions.Open` can reuse a verified non-ask control master through mux proxy mode; ask/autoask actions use the caller-provided `Control_Master_Approval_Callback` and return `Cancelled` when no callback is configured or the callback denies the action. Hidden master spawning remains caller-owned through the explicit helper. `SSH_Lib.Mux` provides the corresponding bounded OpenSSH control mux framing, ext-info/proxy opcodes, Unix control client/master lifecycle with owned control-path unlinking on close, Unix `SCM_RIGHTS` descriptor passing and OpenSSH-sequenced stdin/stdout/stderr helpers for passenger fds, typed new-session and forwarding payload helpers, validated backend request classification, hello-negotiating control-client processing, callback dispatch for passenger session/forward/proxy backends with validated backend responses, bounded control-master serving, an owning single-client serve overload for mux proxy handoff, alive/terminate/stop-listening routing, alive pid, session-opened, remote-port, exit-message, TTY-failure, ext-info, proxy, and failure-reason responses, and deterministic idle-timeout policy for parsed `ControlPersist` values. `Expand_Local_Command` returns an empty command unless `PermitLocalCommand` is enabled, expands `%%`, `%d`, `%h`, `%n`, `%p`, `%r`, `%l`, and `%L`, and rejects unknown tokens or control characters; execution remains an explicit caller decision.

`Load_Default` should read the default config location through Ada path/environment helpers. Default tests must not depend on the user’s real SSH config.
